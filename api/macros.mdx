The `tracing` crate exposes its entire instrumentation surface through declarative macros. Rather than calling constructors directly, you use macros to create spans, fire events, and probe whether a given level is currently enabled. All macros accept an optional `target:` attribute to override the default module-path target, a `parent:` attribute to override the default contextual parent, and a `name:` attribute (event macros only) to override the synthetic event name derived from the file and line number.

<Tabs>
  <Tab title="Span Macros">

Span macros return a [`Span`](/api/span) value. Spans are not entered automatically — you must call `.enter()`, `.entered()`, or `.in_scope(|| ...)` to make a span the active context.

---

### `span!`

The generic span-creation macro. All level-specific span macros delegate to this one.

```text
span!(level, name)
span!(level, name, field = value, ...)
span!(target: "my_target", level, name, field = value, ...)
span!(parent: &parent_span, level, name, field = value, ...)
span!(target: "t", parent: &p, level, name, field = value, ...)
```

**Parameters**

| Parameter | Type | Description |
|-----------|------|-------------|
| `level` | `Level` | Verbosity level (`Level::TRACE` … `Level::ERROR`) |
| `name` | `&'static str` | Human-readable span name |
| `field = value` | key-value pairs | Structured fields recorded at span creation |
| `target:` | `&str` (optional) | Override the log target (defaults to `module_path!()`) |
| `parent:` | `impl Into<Option<Id>>` (optional) | Explicit parent span (defaults to current context) |

**Field value formats**

| Syntax | Serialization |
|--------|---------------|
| `key = value` | Recorded as a typed `Value` |
| `?key` / `?key = expr` | Recorded via `fmt::Debug` |
| `%key` / `%key = expr` | Recorded via `fmt::Display` |
| `key` (bare ident) | Shorthand for `key = key` — records the local variable |
| `key = field::Empty` | Reserves the field; fill it later with `span.record(...)` |

```rust
use tracing::{span, Level};

let request_id = 42u64;
let span = span!(
    Level::INFO,
    "handle_request",
    request_id,          // shorthand: records local var
    method = "GET",      // plain value
    path = %"/api/v1",   // Display format
    body = ?some_struct, // Debug format
);
let _enter = span.enter();
// work happens here
```

### `trace_span!`

Constructs a span at `Level::TRACE`. Equivalent to `span!(Level::TRACE, ...)`.

```text
trace_span!(name)
trace_span!(name, field = value, ...)
trace_span!(target: "my_target", name, field = value, ...)
trace_span!(parent: &parent, name, field = value, ...)
```

```rust
use tracing::trace_span;

let span = trace_span!("db_query", sql = "SELECT 1");
let _enter = span.enter();
```

### `debug_span!`

Constructs a span at `Level::DEBUG`. Equivalent to `span!(Level::DEBUG, ...)`.

```text
debug_span!(name)
debug_span!(name, field = value, ...)
debug_span!(target: "my_target", name, field = value, ...)
debug_span!(parent: &parent, name, field = value, ...)
```

```rust
use tracing::debug_span;

let span = debug_span!("parse_config", path = "/etc/app.toml");

```

  <Tab title="Event Macros">

Event macros immediately record a single point-in-time observation and dispatch it to the current subscriber. Unlike span macros they do not return a value.

---

### `event!`

The generic event macro. All level-specific event macros delegate to this one.

```text
event!(level, "message")
event!(level, field = value, ..., "message")
event!(level, field = value, ...)
event!(target: "my_target", level, field = value, ..., "message")
event!(parent: &span, level, field = value, ..., "message")
event!(name: "custom_name", level, field = value, ..., "message")
```

The final positional arguments are treated as a `format_args!`-style message, which becomes an implicit `message` field.

```rust
use tracing::{event, Level};

let bytes_written: usize = 1024;
event!(Level::INFO, bytes = bytes_written, "flushed buffer");

// Format string works just like format!()
event!(Level::WARN, user_id = 99, "rate limit exceeded: {} req/s", rate);

// Explicit parent
event!(parent: &my_span, Level::DEBUG, "sub-operation complete");
```

```text
trace!("message")

```

```rust
use tracing::trace;
```

### Field value formats (event macros)

The same field sigil syntax used in span macros applies to event macros:

| Syntax | Serialization |
|--------|---------------|
| `key = expr` | Typed `Value` (implements `tracing::Value`) |
| `?key` / `?key = expr` | Uses `fmt::Debug` |
| `%key` / `%key = expr` | Uses `fmt::Display` |
| `key` (bare ident) | Shorthand for `key = key` |

<Note>
Unlike spans, events must have a value for every field they declare at the call site — there is no `field::Empty` deferred-recording for events.
</Note>

  <Tab title="Utility Macros">

These macros let you query the current subscriber before performing expensive work, avoiding the cost of building arguments that would ultimately be discarded.

---

### `enabled!`

Tests whether a span **or** event with the given level (and optional target / fields) would be recorded by the current subscriber. Returns `bool`.

```text
enabled!(level) -> bool
enabled!(level, field_name) -> bool
enabled!(target: "my_target", level) -> bool
```

```rust
use tracing::{enabled, Level};

if enabled!(Level::DEBUG) {
    let expensive = compute_debug_snapshot();
    debug!(snapshot = ?expensive, "captured state");
}
```

<Tip>
`enabled!` may return false positives or false negatives when the subscriber's filter is more specific than the metadata provided (e.g., it filters by field values). Use it only as a performance hint.
</Tip>

---

### `event_enabled!`

Like `enabled!`, but signals to the subscriber that the caller is checking for an **event** specifically (sets `Kind::EVENT` on the hint callsite). Returns `bool`.

```text
event_enabled!(level) -> bool
event_enabled!(level, field_name) -> bool
event_enabled!(target: "my_target", level) -> bool
```

```rust
use tracing::{event_enabled, Level};

if event_enabled!(target: "audit", Level::INFO) {
    let audit_record = build_audit_record(&ctx);
    info!(target: "audit", record = ?audit_record, "access granted");
}
```

---

### `span_enabled!`

Like `enabled!`, but signals to the subscriber that the caller is checking for a **span** specifically (sets `Kind::SPAN` on the hint callsite). Returns `bool`.

```text
span_enabled!(level) -> bool
span_enabled!(level, field_name) -> bool
span_enabled!(target: "my_target", level) -> bool
```

```rust
use tracing::{span_enabled, Level, info_span};

if span_enabled!(Level::INFO) {
    let span = info_span!("expensive_operation", input = ?large_value);
    let _guard = span.entered();
    perform_work();
}
```

---

### `record_all!`

Records multiple fields on an existing span in a single call. Accepts the same `key = value, ...` syntax as span creation macros, including `?key` (Debug) and `%key` (Display) sigils. All fields must have been declared (possibly with `field::Empty`) when the span was created.

```text
record_all!(span, field1 = value1, field2 = value2, ...)
record_all!(span, ?field1, %field2 = expr, ...)
```

```rust
use tracing::{info_span, field, record_all};

let span = info_span!(
    "request",
    request_id = field::Empty,
    status     = field::Empty,
    user       = field::Empty,
).entered();

// ... process request ...

record_all!(span, request_id = req.id, status = 200i64, user = %req.user);
```

<Tip>
`record_all!` is more ergonomic than calling `span.record(...)` once per field when you have several values to record at the same point in time.
</Tip>
