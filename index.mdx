Tracing is a framework for instrumenting Rust programs to collect structured, event-based diagnostic information. Unlike traditional log lines, `tracing` captures *spans* — periods of execution with a beginning and end — alongside *events* that record discrete moments. This gives you full causal context across async tasks, threads, and library boundaries.

## Why Tracing?

In asynchronous systems, traditional log messages are difficult to interpret because individual tasks are multiplexed on the same thread, causing log lines from different tasks to intermix. `tracing` solves this by associating every event with the span context in which it occurs.

## Get Started

<Steps>
  <Step title="Add dependencies">
    Add `tracing` and `tracing-subscriber` to your `Cargo.toml`:
    ```toml Cargo.toml
    [dependencies]
    tracing = "0.1"
    tracing-subscriber = "0.3"
    ```
  </Step>
  <Step title="Initialize a subscriber">
    In your `main` function, install a global subscriber so trace data is recorded:
    ```rust main.rs
    fn main() {
        tracing_subscriber::fmt::init();
        // your application code here
    }
    ```
  </Step>
  <Step title="Instrument your code">
    Use the `#[instrument]` attribute or macros to emit spans and events:
    ```rust
    use tracing::{info, instrument};

    #[instrument]
    fn process(value: u64) {
        info!(value, "processing item");
    }
    ```
  </Step>
  <Step title="Run and observe">
    Set the `RUST_LOG` environment variable to control what gets logged:
    ```bash
    RUST_LOG=debug cargo run
    ```
  </Step>
</Steps>
